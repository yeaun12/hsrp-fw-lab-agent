# Phase 8 — 통계 이상 탐지 + 이벤트 상관분석

작성일: 2026-10-30 · 대상: 로드맵 Phase 8(P2) / 요청문 §7.1 이상 탐지, §7.2 이벤트 상관분석

## 1. 데이터 평가 먼저 (ML 강행 금지)
로드맵 지침대로 **실제 데이터의 양·품질을 먼저 확인**했다.
- 현재 warehouse: events 1,518건, 관측 기간 **~1일(11시간)**, 심한 편중(ops 1,111 / 보안 21 / 사건 4).
- 환경: **sklearn·numpy 미설치**(경량·저RAM 환경).
- 판정: **ML(Isolation Forest 등)은 보류**가 타당하다. 사유 — 시계열 길이 부족(11h<72h), 표본 부족
  (1,518<2,000), 라이브러리 미설치. 대신 **통계 기준선(중앙값+MAD 로버스트 z)**을 사용한다(표준 라이브러리).
  `anomaly.ml_readiness()`가 이 판정을 데이터에서 자동 산출하며, 데이터가 쌓이면 권장값이 바뀐다.

## 2. §7.1 통계 이상 탐지 (`anomaly.py`)
'평소 상태'를 기준선으로 삼아 벗어나는 지표를 탐지한다. 소표본 왜곡에 강하도록 **중앙값 + MAD**
기반 로버스트 z를 쓰고, **표본이 5개 미만인 계열은 기준선을 세우지 않고 건너뛴다**(오탐 방지).
대상 지표(§7.1 예시): 시간대별 이벤트량·보안 이벤트·경보 발생량, 장비별 활동량, 시간대별 도구 오류율
(연결 실패율 대리), 외부 IP 활동량.

실측(real data): `시간대별 이벤트량` 기준선(중앙값) 69/시간, 표본 11 → **이상 1건: 2026-10-30 14시 446건
(z=5.78)** 탐지(랩 복구 중 오류 폭주). 보안/IP/장비 계열은 표본 부족으로 정직하게 건너뜀.

## 3. §7.2 이벤트 상관분석 (`correlate.py`)
여러 경보를 별개로 두지 않고, **시간 창(기본 300s) + 공유 엔티티(장비·IP)**로 하나의 그룹으로 묶는다.
예: CORE1 장애 → HSRP 전환 → 통신 실패가 짧은 시간에 몰리면 한 그룹. 각 이벤트의 역할을 구분한다:
- **직접 관찰(observed)** — 로그로 직접 관측.
- **연관 확인(correlated)** — 같은 엔티티·시간 창에서 함께 발생.
- **원인 추정(suspected)** — 그룹에서 가장 이르고 심각도 높은 이벤트.
- **검증된 원인(verified)** — 에이전트 조사(incidents)로 실제 확인된 원인(그룹 엔티티를 근거로 언급하고
  시간이 겹치는 사건과 자동 링크).
규칙 기반으로 묶고, **검증되지 않은(모호한) 그룹은 `ambiguous_groups()`로 분리**해 AI(에이전트 조사)가
설명하도록 넘긴다(§7.2 "모호한 관계 조사·설명에 AI 활용"). 결과는 `correlation_groups`·`event_correlations`
테이블에 멱등 저장.

실측(real data): 21개 그룹. 웹 공격(198.51.100.66) 캐스케이드들이 묶였고, **그룹 6·7·9·12는 검증된
원인=사건 #5로 자동 연결**, 13개는 미검증(AI 설명 필요)으로 분류.

## 4. 파일 / 검증
- `agent/anomaly.py`: 데이터 평가 + ML 적정성 판정 + 통계 이상 탐지(CLI).
- `agent/correlate.py`: 규칙 기반 이벤트 상관분석 + 역할 분류 + 검증 원인 링크 + AI 훅(CLI).
- `agent/phase8_test.py`: 합성 데이터 테스트 — robust_z 이상치/무변동, 캐스케이드 군집·검증/미검증 분류·
  멱등성, 시간대별 급증 탐지. **전부 통과.** 두 모듈 모두 실데이터 CLI 실행으로도 검증.

## 5. 한계 (정직한 기록)
- **ML 미적용**: 데이터·환경 부족으로 통계 기준선만 사용. 데이터가 72시간/2,000건 이상 쌓이고 numpy/sklearn를
  설치하면 `ml_readiness`가 권장으로 바뀌며, 동일 특징행렬에 Isolation Forest를 붙여 통계 대비 효용을 비교할
  설계만 남겨 둠(지금 수치를 지어내지 않음).
- **상관분석의 시간 창 한계**: 플러드 구간(예: 랩 복구 중 40건)에서는 300s 창이 서로 다른 원인의 이벤트를
  과다 병합한다. 향후 엔티티별 하위 군집·그래프 기반 연결로 정밀화 가능.
- 상관분석은 Phase 5의 `correlation_id`/`events`·`incidents` 위에서 동작하며, Phase 9 대시보드에서 시각화한다.
